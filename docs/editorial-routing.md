# 新聞發稿分流與產業動態彙整

站方將「是否值得獨立報導」與 `full`／`brief` 篇幅分開判斷。`pipeline/editorial_policy.py` 的 `publication_route()` 只看本次來源標題與摘要；模型稿、歷史背景或來源的宣傳用語不能把例行消息升格，也不能把重大事件降格。

## 分流

- **獨立報導**：重大飛安或廣泛營運衝擊、已取得型別認證等明確里程碑、與臺灣航班或航空業者有直接關係的事件。無法明確判為例行消息時，保留獨立報導路徑；來源與事實驗證仍須通過。
- **產業動態佇列**：小型直升機訂單、單次原型機展示或試飛、一般軟體業務交易、合作備忘錄、生產合作、其他已列明的例行產業消息。模型仍要先完成雙語稿與逐字來源引文驗證；驗證失敗的稿件不得入列。
- **不刊登**：超出航空範圍、沒有足夠可查證資料，或模型按現有編輯契約拒稿的項目。不得為了湊足彙整篇數而補稿。

`data/industry-roundup-queue.json` 只保存已通過站方驗證的例行稿。佇列依來源 URL 去重；每天臺北時間 23:30 後首次執行時，若至少有兩則有效消息，就彙成一篇中英雙語 `articleFormat=roundup` 文章，每篇最多八則。每則保留自己的段落與來源；彼此沒有已知關聯時須明說。未達兩則的項目續留，超過 48 小時仍未刊登便從佇列移除。發稿前再比對 `main` 已刊文章的來源 URL，避免 Muse 延遲提交的稿件被重複收錄。

既有文章不溯及修改或下架。現有每日 briefing 從已刊文章取材，不能代替這個發稿前的佇列。

## Muse 協作

Muse（小助理）是站方免費模型之後、付費模型之前的帶外備援。她的每小時 :20 任務在動筆前與提交前，都要檢查最新 `main` 的 `data/articles/`、`data/industry-roundup-queue.json` 和 `held/feature-drafts`，用來源 URL、事件識別碼及營運人／事件日期去重。已在站方彙整佇列或已刊出的事件，不再建立 `scheduled-*.json` 單篇。

例行產業消息不以 `articleFormat=full` 的單篇繞過站方分流；Muse 仍可處理適合獨立報導的卡稿，並沿用 `writer=scheduled:Meta Muse`、`writerModels=["Meta Muse"]` 及既定 commit 慣例。完整 `cat=feature` 稿仍留在 `held/feature-drafts`，只有 Kass 明確指示才移至 `main`。此檔是共用編輯規則；Muse 個人排程的指令也必須引用它，repo 更新本身不會修改 Muse 的排程或免除 GitHub 寫入核准卡。
