# 新聞發稿分流與產業動態彙整

站方將「是否值得獨立報導」與 `full`／`brief` 篇幅分開判斷。`pipeline/editorial_policy.py` 的 `publication_route()` 先看本次來源標題與摘要，通過驗證後再納入 `articleFormat=brief` 的篇幅判斷；模型稿、歷史背景或來源的宣傳用語不能把例行消息升格，也不能把重大事件降格。

## 分流

- **獨立報導**：重大飛安或廣泛營運衝擊、已取得型別認證等明確里程碑、與臺灣航班或航空業者有直接關係的事件。無法明確判為例行消息時，保留獨立報導路徑；來源與事實驗證仍須通過。
- **產業動態佇列**：沒有直接臺灣關聯的短訊、地方航班／旅客服務調整、小型直升機訂單、概念機展示或試飛、一般軟體業務交易、合作備忘錄、生產合作、例行財報及文件格式更新。模型仍要先完成雙語稿與逐字來源引文驗證；驗證失敗的稿件不得入列。
- **不刊登**：超出航空範圍、沒有足夠可查證資料，或模型按現有編輯契約拒稿的項目。不得為了湊足彙整篇數而補稿。

`data/industry-roundup-queue.json` 保存發稿前已通過核驗的例行稿，或近期站內已刊短篇的逐字摘錄。佇列依來源 URL 去重；每小時正式管線檢查，若至少有兩則有效消息，就彙成一篇中英雙語 `articleFormat=roundup` 文章，每篇最多八則；臺北時間 00–06、06–12、12–18、18–24 每個時段最多一篇。未滿兩則不消耗該時段出刊機會。每則保留自己的段落與來源；彼此沒有已知關聯時須明說。未達兩則的項目續留，超過 48 小時仍未刊登便從佇列移除。發稿前再比對 `main` 已刊文章的來源 URL，避免 Muse 延遲提交的稿件被重複收錄。

另有「已刊短稿」入口：每輪收集近 48 小時、中文正文不超過 600 字且英文正文不超過 450 字的已刊航空文章，涵蓋 Muse 稿件。排除臺灣、飛安、法規、專題及風險標記文章；不覆寫原稿。摘錄沿用原文摘要，編譯前再次確認刊登紀錄、雙語文字與來源完全相符；已收入合輯的文章不再收錄。合輯明示包含已刊摘錄，附原文及原始來源連結，這些摘錄不宣稱是新取得的來源核驗。

最新彙整在發布後 48 小時內保留一個頭條輪播位置，排在編輯置頂與臺灣重點新聞之後；不讓多篇彙整塞滿輪播。已收錄的原文保留頁面，但不再各佔輪播位置；編輯手動置頂仍優先。標題、摘要使用實際收錄的消息標題，每則正文附自己的小標、內容與來源。

`data/stats.json` 的 `newsWriter` 記錄本輪入列數、待彙整數、最近時段及本輪發布的彙整 ID，可判斷流程是否真正運作。

既有文章不溯及修改或下架。現有每日 briefing 從已刊文章取材，不能代替這個發稿前的佇列。

## Muse 協作

Muse（小助理）是Luna 之後的帶外備援（依 2026-11-04 確認的順序）。她的每小時 :20 任務在動筆前與提交前，都要檢查最新 `main` 的 `data/articles/`、`data/industry-roundup-queue.json` 和 `held/feature-drafts`，用來源 URL、事件識別碼及營運人／事件日期去重。已在站方彙整佇列或已刊出的事件，不再建立 `scheduled-*.json` 單篇。

例行產業消息不以 `articleFormat=full` 的單篇繞過站方分流；Muse 仍可處理適合獨立報導的卡稿，並沿用 `writer=scheduled:Meta Muse`、`writerModels=["Meta Muse"]` 及既定 commit 慣例。完整 `cat=feature` 稿仍留在 `held/feature-drafts`，只有 Kass 明確指示才移至 `main`。此檔是共用編輯規則；Muse 個人排程的指令也必須引用它，repo 更新本身不會修改 Muse 的排程或免除 GitHub 寫入核准卡。
